# 追加の練習項目

CountDown は「正則型 + 二項演算」への一般化という一本の軸でよく効いている。
ここからの練習は、同じ姿勢（**要求する性質を最小にして、効率は落とさない**）を別のアルゴリズムに移すものと、CountDown 自体をもう一段抽象するものに分ける。

各項目は次の形で書く。

- **出発点**: 具体的な（多くの場合 `int` の）アルゴリズム
- **命題**: どの概念に置き換えられるか
- **効率**: 一般化しても残したい計算量・枝刈り
- **非自明な使い方**: 同じコードの別解釈

参考文献との対応は [generic_programming.md](generic_programming.md) を参照。

---

## 0. いまの CountDown から自然に続くもの

すでにメモされている未実装の型は、新しいアルゴリズムというより **同じソルバーのモデル** なので、ここは短く置く。

| 型 | 演算の例 | 見たい現象 |
| --- | --- | --- |
| 有理数 / 複素数 | `+ - * /` | 平面上の点への到達（既存メモの延長） |
| 行列 | `+ - *` | 非可換積。`valid` の対称性除去が効かない |
| 多項式 | `+ - *` | 次数・係数の制約で探索空間が変わる |
| 関数 `T → T` | 合成、点ごと演算 | 「操作の列」そのものが値 |
| リスト | 連結、zipWith | 単位元（空リスト）と結合法則 |

これらを足す前に、下の **概念の階層化** を先にやると、`Op<T>` の `valid` に埋め込んでいる交換法則・単位元の知識が再利用できる。

---

## 1. 概念の階層化（CountDown のリファクタ）

**出発点**: いまの `Op<T>`（名前・適用・`valid`）

**命題**: アルゴリズムが本当に必要としているのは「二項演算がある」ことではなく、その演算が満たす代数的性質である。

Dart には型クラスがないので、次のような階層を **明示的なオブジェクト** として置く練習になる。

```
Magma        閉じた二項演算
Semigroup    結合法則
Monoid       単位元
Group        逆元
Commutative* 交換法則
Semiring     二つのモノイドが分配する
Ring / Field
EuclideanDomain
```

CountDown の `valid` がやっていること（`x >= y` で交換法則の重複を落とす、単位元を除外する）は、演算の **性質から機械的に導ける枝刈り** である。性質をデータにすると、集合・モジュロ・行列で毎回 `valid` を手書きしなくてよくなる。

**効率**: 交換法則による対称性除去、単位元の除外は、一般化しても CountDown と同じ回数の式生成で済むこと。

**非自明な使い方**: 「過大な制約」を意図的に入れて壊す。例えば行列積に交換法則を仮定すると解が落ちる。どの性質がどの最適化の前提かを実験できる。

---

## 2. 累乗（二分累乗）

**出発点**: `int pow(int a, int n)` を繰り返し二乗で計算する。

**命題**: 底 `a` の型は、結合的な二項演算を持つ型（半群 / モノイド）に置き換えられる。指数だけが自然数。

```
power(a, n) = a ⊕ a ⊕ ... ⊕ a   (n 回)
```

**効率**: `O(log n)` 回の演算を保つ。結合法則がないと二乗が意味をなさない。単位元があると `n = 0` も扱える。

**非自明な使い方**

- 行列の累乗（漸化式・グラフの長さちょうど `n` の経路）
- 関数合成の繰り返し `f ∘ f ∘ ... ∘ f`
- モジュロ乗法（既存の `ModuloInt` を再利用）
- 文字列モノイドでの繰り返し（ここでは演算回数が同じでも各演算が重い、という効率の話ができる）

CountDown が「どの演算を選ぶか」の探索なのに対し、こちらは **演算は一つ、回数だけが指数** という対になる練習。

---

## 3. エジプト式乗法（倍々と足し算）

**出発点**: 古代エジプト / ロシア農民乗法。加法と「2 倍」だけで積を得る。

**命題**: 「整数の乗法」は、「可換半群の元 `a` を、自然数 `n` 回 ⊕ する」ことに置き換えられる。必要な操作は

- `a ⊕ a`（doubling）
- 奇数判定に相当する指数側の操作

だけである。

**効率**: `O(log n)` 回の ⊕。`n * a` を `a` を `n` 回足す実装より演算回数が少ないことを、型が変わっても測れる。

**非自明な使い方**

- ベクトル・多項式・変換のスカラー倍（ここでの「スカラー」は自然数）
- 「移動を n 回合成する」幾何（複素数・行列の話とつながる）

FMGP の導入例そのものなので、CountDown の次に短い実装で概念（必要な操作の最小化）を体感しやすい。

---

## 4. ユークリッドの互除法

**出発点**: `gcd(int a, int b)`

**命題**: `int` はユークリッド整域に置き換えられる。必要なのは

- 整除できること（または引き算で減少すること）
- ノルムが strictly に減ること

**効率**: 剰余を使う版は引き算版より速い。一般化後も「ノルムの減少」が停止と計算量を支える。ノルムが弱い型に無理に移植すると停止しなくなる、という反例も練習になる。

**非自明な使い方**

- 多項式環の gcd（約分・通分）
- ガウス整数
- 有理数の正規化（CountDown の有理数モデルの前処理）

「等価性」と「大きさ」が `int` 以外で何を意味するかが、正則型の話の続きになる。

---

## 5. 半環上の経路計算（Floyd–Warshall / 行列累乗）

**出発点**: 隣接行列の最短路、または到達可能性。

**命題**: 三重ループ（または隣接行列の累乗）は、辺の重みが半環の元であれば同じまま動く。

| 半環 | `⊕`（合流） | `⊗`（接続） | 意味 |
| --- | --- | --- | --- |
| トロピカル | `min` | `+` | 最短路 |
| 通常の数 | `+` | `*` | 経路の数え上げ |
| ブール | `∨` | `∧` | 到達可能性 |
| マックス・ミニ | `max` | `min` | ボトルネック容量 |
| 正規表現 | `∪` | 連結 | 経路の言語 |

**効率**: `O(n³)` 回の `⊕` / `⊗` を保つ。実装を変えずに意味だけが変わる、というのがこのリポジトリの「自明でない新しい使い方」に最も近い。

**非自明な使い方**: CountDown の式探索を「演算の半環」として見直す。値の到達可能性（ブール）と、式の数え上げ（通常の半環）と、最短の式（演算回数を距離にしたトロピカル）が同じ走査で出る。

---

## 6. 畳み込み（fold）と結合法則

**出発点**: リストの総和 `sum`。

**命題**: 左畳み込みは任意の二項演算で動く。結合法則があるときだけ分割統治・並列化ができる。単位元があるときだけ空列が自然に扱える。

**効率**: 非結合な演算に reduce を並列化すると結果が変わる。一般化で効率を「上げる」条件（結合法則）と、上げてはいけない条件を対で見る。

**非自明な使い方**

- 区間の min / max（べき等モノイド）
- 行列積の列（非可換。結合はするが並列の分割点が結果の括弧付けを変えない）
- `Expr.eval` / `values` / `toString` を単一の fold にする（下の木の畳み込みへ）

CountDown の `results` がリストの分割で再帰しているので、「結合的なら分割の仕方を自由にしてよい」と比較すると、なぜ CountDown では分割の仕方自体が解の一部なのかがはっきりする。

---

## 7. 木の畳み込み（catamorphism）

**出発点**: `Expr.eval` と `Expr.values` と `Expr.toString`。

**命題**: 二分木上の再帰は、葉と節で何をするかだけを差し替えられる。`eval` は「節 = 演算を適用」という一つの代数である。

**効率**: 走査は一度でよい。いまは `eval` と `values` が別々に木を降りる。一つにまとめても漸近計算量は同じで、定数倍は下がる（banana split）。

**非自明な使い方**

- 式の複雑さ（演算回数・深さ）を同じ走査で測り、CountDown の解を最短式優先にする
- 同じ木に別の代数（モジュロ、集合）を載せる。木の形は再利用、解釈だけ差し替え

これは CountDown のコードを「汎用的にする」練習として、新しいソルバーを書くより小さい。

---

## 8. 二分探索（単調述語の境界）

**出発点**: 整列済み `List<int>` から値を探す。

**命題**: 探しているのは値そのものではなく、単調な述語 `p` が `false` から `true` に変わる境界である。列の要素型は全順序である必要すらなく、インデックス上で `p` が単調ならよい。

**効率**: 比較（または `p` の評価）が `O(log n)` 回。ランダムアクセスが必要。`Iterable` にそのまま移植すると線形に落ちる、という「一般化が効率を壊す」反例になる。

**非自明な使い方**

- 実数上の方程式の根（連続版）
- 「この演算回数以下で到達できるか」の判定を CountDown の探索に使う
- lower_bound / upper_bound の組で多重度を取る

---

## 9. 比較に基づく選択・整列

**出発点**: `min` / `sort`。

**命題**: 要素型ではなく、比較関係（厳密には strict weak order）だけが必要。安定性・比較回数はアルゴリズムの性質で、要素の中身に依存しない。

**効率**: 比較回数の上界を、`int` でも `Expr<T>` でも同じに保つ。比較が重い型（行列、集合）では、比較回数を減らすアルゴリズムの差が見える。

**非自明な使い方**: CountDown の解を「式の大きさ」「使った値の個数」「演算の種類」で並べる。比較関数を差し替えるだけで、同じ `solutions` の出力から別の最適解を取る。

---

## 10. 探索そのものの一般化

**出発点**: `CountDownProblemGenericSolver.solutions`。

**命題**: いまのソルバーは次の 3 つに分けられる。

1. 素材の列から部分列・順列を取る（`choices`）
2. 二項演算の木を生成する（`results`）
3. 値の等価で濾す（`== x`）

3 を任意の述語 `T → bool` にすると、「目標値に等しい」以外の問題になる。2 の木生成は「マグマの自由な式」であり、演算が結合的・可換なら正規形に潰せる。

**効率**: `valid` と交換法則による枝刈り、途中値のメモ化は、述語が変わっても使える。述語が単調なら 8. の二分探索と合成できる。

**非自明な使い方**

- 「値が目標の約数」「集合が目標を包含する」など、等価以外の目標
- 目標から逆算する（群なら逆元があるので、前向き生成より狭い）
- meet-in-the-middle（列を半分に分けて表を持つ）で指数時間を抑える

---

## 11. 線形代数（ガウス消去・行列積）

**出発点**: 実数行列の連立方程式。

**命題**: ガウス消去は体であれば動く。行列積は半環でも動く（5. と接続）。

**効率**: 枢軸選択の回数・演算回数は次元だけに依存する。体の演算が遅い（有理数の桁増大、多項式）とき、アルゴリズムの構造は同じでも定数が爆発する。一般化のあと「どの演算のコストを数えるか」を測る練習になる。

**非自明な使い方**

- `GF(p)`（既存モジュロと接続）
- 隣接行列の積 = 経路（再び 5.）
- CountDown の線形な式だけを行列で表す、という見方

---

## 12. 点ごと演算と「同じ形」

**出発点**: リストの `zipWith(+)`。

**命題**: 同じ形の構造があれば、中身の演算を持ち上げられる。リスト、木、行列、関数 `X → T`。

**効率**: 構造の走査は一度。中身の `+` を汎用にしても、走査回数は増えない。関数型への持ち上げは「各点で独立」なので、遅延すれば必要な点だけ計算できる。

**非自明な使い方**: CountDown メモの「加減乗除が定義された型の値を返す関数型」。点ごと演算と合成を両方 `Op` にすると、式は「関数を組み立てる式」になる。

---

## 進め方の提案

実装の大きさ順で、既存コードとの距離が近いものから。

1. **概念の階層化** — `Op` / `valid` の知識を再利用する土台
2. **木の畳み込み** — いまの `Expr` を小さく一般化する
3. **二分累乗** または **エジプト式乗法** — 短い単一演算の練習（FMGP）
4. **gcd** — 「減少するノルム」という別種の概念
5. **半環上の経路** — 同じコードの別解釈が最もはっきり出る
6. CountDown の未実装モデル（行列・複素数・多項式）は、1. のあとだと `valid` を量産しなくて済む
7. **探索の一般化** — CountDown の次の本体になりうる

「効率を落とさない」を毎回テストできるとよい。同じ入力で、具体版と一般版の演算回数（または生成した式の個数）を数えて等しいことを見る、というテストの型を CountDown から流用できる。
